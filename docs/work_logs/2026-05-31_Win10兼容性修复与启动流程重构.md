## 二、问题与修复详情

### 1. WSL 检测失败（`wsl --version` 在 Win10 不可用）

**现象**：应用卡在"需要启用 WSL"，点击重试无反应，但系统已启用 WSL2。

**根因**：`wsl --version` 是 Store 版本 WSL（Win11 默认）的命令。Win10 inbox WSL 不支持此参数，返回非零退出码。原始代码 `is_wsl_enabled()` 仅靠此命令判断。

**修复**：`is_wsl_enabled()` 改用 `wsl --status`（Win10/Win11 均支持），失败时回退到 `wsl --list --quiet`（最低兼容方案）。两层探测覆盖所有 WSL 版本。

### 2. WSL 输出 UTF-16LE 编码导致发行版匹配失败

**现象**：`is_distro_registered()` 始终返回 false，即使 `wsl --list` 能看到 `HermesLinux`。

**根因**：`wsl.exe` CLI 在 Windows 上输出 UTF-16LE 编码（每个 ASCII 字符后跟 `\0`）。原始代码用 `String::from_utf8_lossy` + `trim_matches('\0')` 解码，无法正确处理交错的 null 字节，字符串比对永远不等。

**修复**：新增 `decode_wsl_output()` 函数——检测 UTF-16LE 特征（偶数长度 + 高位 null），正确调用 `String::from_utf16_lossy` 解码。UTF-8 输出走原路径。

### 3. WSL2 VM 启动后立即关闭

**现象**：`start-services.sh` 执行完毕后，`hermes-agent` 和 `hermes-webui` 进程在几秒内被杀死。

**根因**：Win10 inbox WSL2 在最后一个 session 结束后会自动关闭 Lightweight Utility VM。`start-services.sh` 用 `nohup` 启动后台进程后退出，此时无活跃 session，VM 关闭，所有进程随之终止。Win11 WSL2 有 8 秒+ 的 idle 超时且可配置，行为不同。

**修复**：`start_services()` 改为 `bash -c "bash start-services.sh 8787 && tail -f /dev/null"`，用 `tail -f` 保持一个永久 session。引入 `WSL_SESSION: Mutex<Option<Child>>` 持有进程句柄，`stop_services()` 时 `kill()` 释放。

### 4. WebView2 无法访问 WSL2 VM IP

**现象**：窗口显示 "172.17.x.x 拒绝连接"。PowerShell `Invoke-WebRequest` 可正常访问同一地址。

**根因**：WebView2（基于 Edge/Chromium）的网络栈不经过 Windows 的 Hyper-V 虚拟网络路由，无法到达 WSL2 VM 的内部 IP（172.17.0.0/16 段）。这是 WebView2 的已知限制，PowerShell 使用 .NET 的 `HttpClient`，走系统路由表，不受此限制。

**修复**：改为优先使用 `localhost:8787`（由 `wslhost.exe` 在 Windows 侧自动创建的端口转发）。若 localhost 不通（部分 Win10 版本转发不可靠），回退到进程内 TCP 代理：绑定 `127.0.0.1:0`（OS 分配端口），异步转发到 WSL VM IP:8787。使用 port 0 而非固定端口，避免 Hyper-V 动态端口保留导致的 `WSAEACCES` (error 10013)。

### 5. iframe 在 Tauri WebView2 中被 CSP 阻止

**现象**：将 iframe src 指向 `http://127.0.0.1:{port}` 后，窗口显示 "127.0.0.1 拒绝连接"。PowerShell 可正常访问同一 URL。

**根因**：Tauri 在 WebView2 中注入 Content Security Policy 头，限制 iframe（`frame-src`）只能加载同源内容。`tauri.conf.json` 设置 `csp: null` 并不禁用 CSP，而是使用 Tauri 生成的默认限制策略。此外，`sandbox` 属性虽缓解了部分问题但无法根治。

**修复**：放弃 iframe 方案，改用 `window.location.href = url` 直接导航整个 WebView 窗口到 WebUI URL。这是顶层导航而非子资源加载，完全不受 CSP/sandbox/跨域约束。导航后 Tauri IPC 不再可用，但服务控制已由 Rust 侧托盘菜单接管，无影响。

### 6. 端口不匹配导致 120 秒超时

**现象**：`Hermes did not become ready within 120 seconds`。

**根因**：`find_available_port(8787)` 尝试 `TcpListener::bind("127.0.0.1", 8787)`，发现已被 `wslhost.exe` 占用（localhost 转发），返回 8788。`start_services(8788)` 传入 8788 作为端口参数，但 WSL 内部服务已在 8787 运行（上次 session 残留），`start-services.sh` 的 `is_running` PID 检查跳过启动。`wait_for_ready` 在 8788 上轮询，永远等不到服务。

**修复**：去除 `find_available_port`，WSL 服务固定使用 8787（常量 `SERVICE_PORT`）。Windows 侧的端口复用由 TCP 代理的 port 0 解决。健康检查改为从 WSL 内部执行 `curl -s -o /dev/null -w '%{http_code}' http://localhost:8787/`，彻底隔离跨 VM 网络问题。

### 7. React StrictMode 双重调用导致端口竞争

**现象**：日志显示 `start_hermes` 被调用两次，两次并发尝试绑定同一代理端口。

**根因**：React 19 的 StrictMode 在开发和生产模式下都可能触发 `useEffect` 双重执行。两次 `start_hermes` 调用并发竞争同一端口资源。

**修复**：Rust 侧用 `static HERMES_URL: Mutex<Option<String>>` 缓存已启动的 URL，第二次调用直接返回缓存值。前端用 `useRef(false)` 作为进入锁，防止重复触发。

### 8. 托盘图标缺失导致窗口无法关闭

**现象**：点击窗口 X 按钮后窗口消失，但进程仍在运行，且无托盘图标可恢复窗口或退出。

**根因**：`on_window_event` 中无条件 `api.prevent_close() + window.hide()`，假设托盘图标一定存在。但托盘创建可能因图标文件缺失等原因静默失败（`setup()` 中 `?` 传播错误直接阻止启动）。

**修复**：`TrayIconBuilder::with_id("main")` 设置明确 ID。`setup()` 中用 `let _ = tray::create_tray()` 容忍失败。`on_window_event` 通过 `app.tray_by_id("main").is_some()` 检查托盘是否存在，仅在有托盘时拦截关闭，否则允许正常退出。

### 9. Setup 页面未区分 WSL 未安装和发行版缺失

**修复**：`check_wsl_ready` 返回结构化 `WslStatus { ready, wsl_installed, distro_registered }`。`Setup.tsx` 根据 `reason` 属性展示不同引导："WSL 未安装"引导运行 `wsl --install`；"发行版缺失"引导重新运行 HermesSetup 安装程序。

## 四、Win11 兼容性评估

所有改动均设计为 Win10/Win11 双向兼容，不存在 Win11 回退风险：

| 改动 | Win10 行为 | Win11 行为 |
|------|-----------|-----------|
| `wsl --status` + `--list` 回退 | `--status` 可能失败，走 `--list` 回退 | `--status` 直接成功 |
| WSL session keep-alive | 必须，否则 VM 秒关 | 无害，VM 本身不会自动关闭 |
| WSL 内部 curl 健康检查 | 绕过跨 VM 网络路由问题 | 同样有效 |
| localhost 优先 + proxy 回退 | wslhost 转发可用则走 localhost，否则走 proxy | Win11 localhost 转发始终可用，直接走 localhost，不触发 proxy |
| `window.location.href` 导航 | 不依赖平台 | 不依赖平台 |
